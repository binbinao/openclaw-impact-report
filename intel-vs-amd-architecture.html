Intel 环形总线 vs AMD 小芯粒

一篇文章搞懂两巨头芯片架构的核心差异

一句话概括：Intel 是"一个环形跑道串起所有人"，AMD 是"多个小分队 + 中央指挥部"。Intel 适合低延迟（游戏/桌面），AMD 适合堆核心数（服务器/EPYC）。

Intel 环形总线（Ring Bus）

想象一个环形跑道，CPU 核心、缓存、内存控制器、IO 接口都挂在跑道边上。数据在跑道上顺时针或逆时针跑，跑到目的地就下车。

        ┌──────────────────────────┐
        │    Core 0    Core 1      │
        │      │         │         │
   ┌────┼──────┼─────────┼─────┼────┐
   │    │   ┌──┴─────────┴──┐  │    │
   │  IO    │   RING BUS    │ Cache │
   │    │   └──┬─────────┬──┘  │    │
   └────┼──────┼─────────┼─────┼────┘
        │      │         │         │
        │    Core 2    Core 3      │
        └──────────────────────────┘

优点

  • 延迟低——核心间通信快，数据跑半圈就到目的地
  • 设计简单——所有核心共享同一个 L3 缓存，一致性协议简单

缺点

  • 核心越多，跑道越堵——超过 10-12 个核，环形总线就成了瓶颈
  • 一个核坏了，整个跑道受影响

AMD 小芯粒（Chiplet）

AMD 的做法是把大芯片拆成多个小芯片，每个 CCD（Core Complex Die）是独立小芯片，通过 Infinity Fabric 总线连接到中央 IOD。

   ┌──────────────┐   ┌──────────────┐
   │    CCD 0     │   │    CCD 1     │
   │  8核 + L3    │   │  8核 + L3    │
   └──────┬───────┘   └──────┬───────┘
          │     Infinity     │
          │     Fabric       │
          └────────┬─────────┘
          ┌────────┴─────────┐
          │       IOD        │
          │  内存控制器 + IO  │
          └──────────────────┘

优点

  • 良率高、成本低——小芯片做坏的概率远低于大芯片
  • 制程混搭——CCD 用最先进 5nm/3nm，IOD 用便宜的 12nm
  • 轻松堆核——可以堆到 96/128 核

缺点

  • 跨 CCD 延迟高——核心 0 访问 CCD 1 的缓存，得绕一大圈经过 IOD
  • 两个 CCD 之间通信要经过中央 IOD 中转

全面对比

维度Intel 环形总线AMD 小芯粒
结构一块大芯片，所有东西挂环形跑道多个小芯粒 + 中央 IOD
核心数≤ 12 核96+ 核
核心间延迟低 半圈就到高 跨 CCD 绕远路
良率 / 成本低良率，贵高良率，便宜

现在的演进

Intel 也不死守环形了

  • 12 代酷睿引入大小核混合架构（P-core + E-core）
  • Meteor Lake 引入 Tile 架构（类似 Chiplet，但用 Foveros 3D 堆叠 + EMIB 桥接）
  • 现在走的是"环形 + Mesh + Tile"混合路线

AMD 也在补延迟短板

  • 3D V-Cache——额外 L3 缓存垂直堆叠在 CCD 上方，大幅降低缓存延迟
  • 对游戏性能提升巨大（Ryzen 7 9800X3D 成为游戏神 U）
总结：Intel 是"一条跑道串所有"，AMD 是"多个小分队 + 中央指挥部"。但两者现在都在往对方的方向靠——Intel 学 Chiplet，AMD 补延迟。
