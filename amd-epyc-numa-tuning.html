AMD EPYC CCD NUMA 调优实战

从零代码到改通信层——三阶段调优指南，以及算例业务层是否受影响

核心结论：绝大多数 CFD 团队只需要改启动命令（零代码），就能拿到 20-50% 的性能提升。需要改代码的深度调优，通常只有 HPC 国家实验室或求解器开发商才会做。

L1 最简单：只改启动命令（零代码）

不改任何算例代码，纯运维操作，5 分钟搞定。

# 查看 NUMA 拓扑 numactl --hardware # 典型 AMD EPYC 双路输出： # node 0: CCD 0-3 (cores 0-31) # node 1: CCD 4-7 (cores 32-63) # node 2: CCD 0-3 (cores 64-95) ← 第二个 CPU # node 3: CCD 4-7 (cores 96-127) # 把 MPI rank 绑定到指定 NUMA 域 mpirun -np 128 \ --map-by ppr:32:numa \ --bind-to core \ ./solver

--map-by ppr:32:numa 意思是每个 NUMA 域放 32 个进程，确保相邻 rank 在同一个 CCD 内。Halo Exchange 的相邻 rank 大概率落在同 CCD 内，延迟从跨 CCD 的 ~200ns 降到同 CCD 的 ~50ns。

操作涉及代码耗时收益
mpirun --map-by + numactl❌ 零代码5 分钟10-30%

L2 中等：理解网格分区（不改代码）

开始触及算例元数据，但不改求解器源码。关键问题：网格分区器（METIS/Scotch）不知道 NUMA 拓扑。

方案 A：重排 rank 顺序

mpirun -np 128 \ --map-by ppr:32:numa:PE=1 \ --rank-by numa \ --bind-to core \ ./solver

方案 B：拓扑感知通信

// OpenFOAM 的 system/controlDict mpiBufferSize 0; // 让 MPI 自动管理

需要理解网格分区结果和 NUMA 拓扑的对应关系，可能需要重排 rank 或调整分区策略。

操作涉及代码耗时收益
重排 rank + 调整分区策略❌ 不改代码1-2 天额外 10-20%

L3 深度：改通信层（需改代码）

需要修改求解器源码，但改的是通信层，不改物理模型。

3.1 异步通信 + 计算重叠

// 原始代码（同步通信） updateBoundary(); // 等 Halo 数据到达 solve(UEqn); // 然后计算 // 改为异步重叠 MPI_Irecv(halo_data); // 非阻塞接收 solve(inner_cells); // 先算内部网格（不依赖 Halo） MPI_Wait(halo_complete); // 等 Halo 数据到 solve(boundary_cells); // 再算边界

收益：Halo Exchange 的延迟被内部计算掩盖，对 CFD 迭代整体时间影响显著降低。

3.2 NUMA 感知内存分配

// 确保每个 MPI rank 的数据在本地 NUMA 域 #include <hwloc.h> hwloc_topology_t topology; hwloc_topology_init(&topology); hwloc_topology_load(topology); // 在本地 NUMA 域分配网格数据 void* local_data = hwloc_alloc_membind( topology, size, hwloc_get_numa_node_objs(topology), HWLOC_MEMBIND_BIND, 0 );
操作涉及代码耗时收益
异步通信重叠 + NUMA 感知分配✅ 改通信层1-2 周额外 10-15%

算例业务层是否受影响？

绝大多数情况下不需要动算例。

需要改什么

  • ✅ MPI 启动参数（--map-by）
  • ✅ 网格分区策略（分区器选择）
  • ✅ 内存分配策略（numactl）
  • ✅ 通信模式（同步→异步重叠）

不动什么

  • ❌ 物理模型（湍流、燃烧、多相等）
  • ❌ 边界条件
  • ❌ 求解器算法
  • ❌ 网格文件
  • ❌ 后处理
唯一例外：极度不均匀的网格（如局部极端加密）可能导致分区器产生的子域大小悬殊，某些 CCD 满载而其他 CCD 空闲。这时需要改分区策略——但这属于预处理阶段，不涉及求解器。

调优复杂度总览

层级操作涉及代码耗时收益
L1mpirun --map-by + numactl零代码5 分钟10-30%
L2重排 rank + 调整分区策略不改代码1-2 天+10-20%
L3异步通信重叠 + NUMA 感知分配改通信层1-2 周+10-15%
L4改物理模型——不需要
实战建议：先做 L1，5 分钟拿到最大收益。如果 L1 后性能仍未达预期，再逐步推进到 L2。L3 仅建议有 HPC 专责工程师的团队尝试——维护私有代码分支的长期成本通常超过那 10-15% 的额外收益。
