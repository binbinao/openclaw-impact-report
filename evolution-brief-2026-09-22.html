容量预算（本期新增的量化规则）

P116 只说了「本期已归档则可推翻」，没给预算。本期把「期数」算了出来：

  • self-evolution 单期增量 = 6,181 chars（P116 自身条目：Pitfalls +3,595 ／ Current Status +2,586）
  • 预算式：可支撑期数 = 余量 / 单期增量 = 18,214 / 6,181 ≈ 2.9 期 → P120–P121 二次撞墙（除非再次归档）
  • 本期执行结果（实测）：SKILL.md 81,786 → 83,591 chars（P117 条目 +4,225，迁出 P104–P108 −2,420 → 净增仅 1,805），余量 16,409。按本期节奏（1,805/期）可支撑 9.1 期；按 P116 节奏（6,181/期）仅 2.7 期 → 预算结论对「单期增量」高度敏感，记录纪律本身就是那个变量
  • ai-news-digest 的构成与 P116 前的 self-evolution 同构：## Pitfalls 49,232 (55.2%) ／ ## Procedure 25,152 ／ ## References 10,151——同样是「逐期追加的发现日志」主导
  • 它的 references/ 里已存有 20+ 个 cron-*-session.md（作者已有「日志外置」习惯），但 ## Pitfalls 仍在主载体里累积 → 治理只做了一半
结论：容量治理不是一次性的重构，而是需要每期阅读预算的持续纪律。本期已把 P104–P108 的历史条目迁出 Current Status（见文末变更记录）。
F2 · tools.approval 被识别为「活动计数器」，而不是错误率

tools.approval 长期占据日总量 62–69%（本期 70 条 = 68.6%），一直是报告里的「头号真实错误源」。本期用本作业自身做了一次仪器化测量：

测量项实测含义
本会话 terminal 调用数15全程 09:00:52 → 收尾（含 2 次被安全层阻断）
同期 09h approval 警告（3 次采样）2012（9 次调用）→ 14（11 次）→ 20（15 次）
比例（告警 / terminal 调用）1.33同阶但非严格 1:1（实测 1.0–1.5）→ 仅可作「活动代理」，不可作精确计数
被安全层阻断的调用2python3 -c、heredoc 各 1 次
pending_approval 记录21:1 精确对应（无其他来源）
r(approval, HN tokens) 跨 7 日0.861高于 r(08h 簇, tokens) = 0.792
tokens / 警告46,643≈ 单轮累积上下文规模

机制：approvals.mode: 'auto' 是非法值 → 每次进入审批评估的工具调用都触发一次「回退到 manual」告警 → 告警数与调用数同阶（实测 1.0–1.5 倍，非严格相等；差值与采样时刻/日志写入时序有关）。因此：

  • 它是 INFRA-activity，与系统健康零因果；正确目标不是「降到 0」，而是「修好 mode 后降到 ~0–1 条/作业」
  • 这同时解释了 P116 测到的 r=0.79：不是「簇 ∝ 被拦截调用」，而是「簇 ∝ 工具调用数」——被拦截者是子集。P116 的结论需修正为更一般的形式
  • 推论：09h 簇与 tokens 无关（r = −0.196）→ 本作业的轮数被固定 prompt 约束，而 token 量不受约束（多轮少调用 / 长上下文）。「活动计数器」只数调用，不数 token

F4 · 自我修正：「每周期计数高度恒定 → INFRA」是错的

P113 立下的 INFRA 判据 (a) 是「每周期计数高度恒定」。本期出现了一个反例，且它完美满足该判据：

组件 / 消息7 日计数方差P113 判据会判为实际性质
tools.registry check_fn13×70INFRA✓ INFRA（设计行为）
hermes_cli.plugins 解析失败6×70INFRA✓ INFRA（插件的已知缺口）
web_extract → ddgs 拒绝2×70INFRA✗ FUNC（真实配置缺陷）

修正后的判据：INFRA / FUNC 只能用消息语义判定——「这条消息描述的是系统的设计行为，还是一次失败？」计数是否恒定与性质无关（确定性缺陷同样零方差）。

这条缺陷（web.extract_backend: '' 空值回退到 ddgs）自 P115 发现以来已连续 9 日零例外，每日 2 条，全部藏在被误标为 INFRA 的容器里。
F5 · 08h 簇 46 → 79（+72%）：P116 的「回落」是分布低端，不是常态
64 → 67 → 53 → 88 → 93 → 46 → 79　（7 日均值 70.0 · sd 17.5 · CV 0.250）
  • P116 判定「2 期持续尖峰 → 回落」成立（依据 P45 的三期规则）。本期 46 → 79 说明：「回落」不是回到稳态，而是同一分布的另一端——7 日区间 46–93 本身就是该分布的波动范围
  • 相关性随样本增加而增强：08h 簇 vs HN 作业 tokens，n=6 时 r=0.789 → n=7 时 r=0.792、ρ=0.679（P116: ρ=0.543）
