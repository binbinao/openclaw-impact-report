🧬 进化建议

🔴 高优先级 — 修复 gateway.run 洪水（79.8% 占比）
问题： PID 3433647 已连续运行 32 天。每次 cron job 尝试启动 gateway 时，检测到已有实例后产生密集的 "Another gateway instance is already running" + "backing off" 错误组合。
建议： 在 cron job 执行前检测 gateway 是否已在运行，避免重复启动。具体方案：
if ! curl -s http://localhost:PORT/health >/dev/null 2>&1; then hermes gateway start; fi
消除后可减少约 80-90% 的日志量。
🟡 中优先级 — 修复 tools.approval 配置错误（68 条/期 WARNING）
问题： config.yaml 中 approvals.mode: auto 为无效值，每分钟产生 1 条 WARNING。P73 中 68 条占非洪水 67.3%，是当前最大单一非洪水源。
建议： 将 approvals.mode 改为 off 或 smart。消除后非洪水基线可回归 25-35 区间（剩余 ~33 条）。
🟡 中优先级 — 配置 API_SERVER_KEY 或禁用 api_server（14 条/期 ERROR）
问题： api_server 持续拒绝启动，每日产生约 80-100 条 ERROR（~12条/h）。
建议： 配置 API_SERVER_KEY 或在 config.yaml 中移除 api_server 平台配置。
🔵 建议 — weakness_scan 添加隐藏弱点追踪（34 期连续 0 检出）
连续 34 期（2.8 个月）的 weakness 0 检出已确认为系统最持久的单一缺陷。建议在 weakness_scan.py 中添加：
• 全文件周期扫描模式（遍历整个日志文件而非仅尾部 500 行）
• 跨组件聚合规则（统计所有配置错误类错误的总和，如 tools.approval + api_server）
• WARNING 级别配置错误检测（同一 WARNING 签名 ≥10 次视为 medium 弱点）
• 隐藏弱点持久跟踪列表（在洪水期间被淹没的弱点，在重现时标注"已重现"而非"新增"）
🔵 建议 — 活跃技能衰减监测（15→14）
活跃技能从 15 降至 14（8 期来首次变化）。建议定期审查技能状态，将不再使用的过期技能清理或归档，避免技能库膨胀（56 过期/70 总数 = 80% 过期率）。
