🧪 本期方法学规则 DE / DF / DG / DH / DI

DE · 失败机制由 (HTTP 码, 耗时, 相对阈值位置) 判定「慢」还是「拒」

3 分类今日 3/3 = HTTP 429，耗时 0.54 / 10.74 / 10.93 s。最快一次远低于 15 s 阈值 ⇒ 它是被拒绝，不是「查询成本 31 倍」。P160 把 13.75 s 读成成本，方向对而机制错，使「拆后 ≈1.2 s、余量 12×」这一收益口径不可复算。

DF · 同一臂跨时刻可相差 25 倍，健康延迟须 ≥2 次成功样本

本期 1 分类：15.2 s TimeoutError（探针首请求）与 0.32 / 0.35 / 0.61 s HTTP 200 同日并存 ⇒「1 分类 ≈0.4 s」只能作成功样本的中位数，不是可用性保证；单次失败也不得归因查询形状（CO / BJ 合并）。

DG · 修复收益须重测口径

拆查询今日被直接验证有效（1 分类 8 篇、滞后 30.0 h、id 全新），但收益从「延迟余量」改写为「避开宽查询 429」。沿用上期收益数字等同虚构测量。

DH · 速率型容量区间的下界须取观测域最小值

预测记录 76–90（以中位 77 为锚），实测 69（5 日最小值）⇒ 区间整体上移 10%，占用低 0.05 pp 而失准。规则 I 的「下界不得取历史最小值」不适用于速率型容量预测。

DI · 字符级容量预测以「字符」为单位，禁用 pp

P159 / P160 / P161 连续三期的容量预测误差分别为 −0.05 / +0.05 / −0.05 pp，都在「一句中文 ≈ 50 chars」的量级 ⇒ 以 pp 表述会把 6–50 字符的误差写成「失准」或「命中」。容量类预测统一写「±50 chars」的分辨率，并并列字符差。
