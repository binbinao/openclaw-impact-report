Intel vs AMD 在千核 CFD 场景下的差异

环形总线 vs Chiplet 的桌面故事，到了 HPC 千核级别需要重新讲

前置修正：千核场景下 Intel 不是环形总线

桌面端 Intel 用环形总线，但服务器端从 Skylake-SP 开始就用 Mesh 网格拓扑。千核 CFD 场景下，对比的是：

级别IntelAMD
桌面（≤12核）环形总线 Ring BusChiplet 1–2 CCD
服务器（≤60核）网格拓扑 MeshChiplet 多 CCD
千核集群多节点 Mesh + 高速互联多节点 Chiplet + 高速互联

CFD 计算的核心特征

CFD 求解器（OpenFOAM、ANSYS Fluent、SU2 等）的典型迭代模式：

# 每次迭代： # 1. 计算本子域内部（计算密集，但通常是 memory-bound） # 2. 与相邻子域交换边界数据（Halo Exchange） # 3. 全局归约（残差/收敛判断，AllReduce） # 4. 循环 → 步骤 1

瓶颈排序

  • 🥇 内存带宽——CFD 是典型的 memory-bound 负载，稀疏矩阵 SpMV 大量时间花在等数据
  • 🥈 Halo Exchange 延迟——每个迭代都要通信，延迟直接乘迭代次数
  • 🥉 计算吞吐——浮点算力反而最不重要

为什么 3D V-Cache 对 CFD 是杀手锏？

CFD 的 SpMV 操作极度依赖缓存。网格节点反复访问相邻节点数据——如果 L3 能装下局部网格，性能直接翻倍。

场景行为瓶颈
无 3D V-Cache局部网格放不下 → 频繁访问 DDR5内存带宽瓶颈
有 3D V-Cache局部网格全在 L3 里 → 极低延迟带宽瓶颈消失

AMD 的 EPYC 9005 系列 3D V-Cache 型号（如 9185X）L3 可达 1.3GB。对于中等规模 CFD（几百万到几千万网格），整个局部子域可以完全放在 L3 里，不需要访问主存。这是 Intel 目前无法匹敌的。

千核场景：关键在于 NUMA 拓扑

到了千核级别（几十个节点），瓶颈从 CPU 内部转移到：

瓶颈影响
网络互联InfiniBand NDR400 vs HPE Slingshot，延迟和带宽决定一切
MPI 实现集合通信（AllReduce）的效率，与 CPU 架构关系不大
负载均衡网格分区质量，与求解器算法有关，与 CPU 无关
NUMA 亲和性MPI rank 与 CCD 的绑定策略——AMD 需要更精细的调优

AMD 的 NUMA 挑战

Chiplet 架构下 NUMA 拓扑更复杂——每个 CCD 是一个 NUMA 域。如果 Halo Exchange 的两个 rank 在同一个 CCD 内，通信极快；如果跨 CCD，延迟高 3-5 倍。

Intel 的 NUMA 优势

Mesh 拓扑的 NUMA 结构更简单，延迟更均匀，不需要过多调优。开箱即用，对缺乏 HPC 调优经验的中小团队更友好。

实战结论

AMD 开箱性能可能不如 Intel——默认 MPI 配置不感知 Chiplet 拓扑。
但通过 numactl + mpirun --map-by 精细调优后，AMD 通常反超。

行业趋势

2024-2026 年 TOP500 和 HPC 集群采购中，AMD EPYC 份额持续增长。美国三大国家实验室（ORNL、LANL、LLNL）的 Frontier、El Capitan 全部采用 AMD EPYC + AMD Instinct GPU。Intel 在纯 CPU HPC 场景的优势在缩小。

最佳实践：AMD EPYC + 精细 NUMA 绑定 + 高速 InfiniBand。
千核 CFD 场景下，CPU 架构差异的影响远小于网络互联和 MPI 调优。
