二、通用场景工作流

场景一：需求 → 交付全流程

最完整的"从需求到知识沉淀"黄金路径，覆盖 5 个产品联动

1
TAPD → 企微通知
产品经理在 TAPD 创建需求，自动推送到企微群并 @ 对应开发
2
Workbody 工作流触发
需求关联的专家工作流自动启动：技术方案评审 → 任务拆分 → 分配执行人
3
Codebody 开发
开发者在 Codebody 中编写代码，AI 辅助 Code Review，提交关联 TAPD 需求单
4
腾讯文档 → 技术方案 / 上线文档
自动生成上线文档模板，关联代码变更记录，多人协同编辑
5
乐享 知识沉淀
文档一键同步至乐享知识库，AI 自动打标签、关联相似案例，形成可检索经验库

场景二：故障应急响应闭环

1
企微群 → 监控告警 / 用户反馈
告警自动推送至企微群，@ 值班人员，附带关键指标截图和日志链接
2
Workbody 应急工作流
预设"故障诊断"专家工作流自动触发：拉取监控数据 → AI 初步分析根因 → 分派责任人
3
Codebody 修复 + TAPD 记录
开发者在 Codebody 中修复代码，自动创建 TAPD 缺陷单，关联 commit
4
企微群 → 腾讯文档 → 乐享
修复完成后，企微群自动推送复盘报告链接，文档沉淀至乐享故障案例库

场景三：会议 → 知识沉淀闭环

1
腾讯会议
会议录制完成，自动生成文字转写和 AI 摘要（关键决策、Action Item）
2
腾讯文档自动生成
会议纪要自动填充到文档模板，@ 对应责任人，同步至企微群
3
乐享知识库归档
文档自动归档到对应项目空间，AI 提取关键知识点，关联历史会议
4
Workbody / Agent 调用
后续工作流可通过 MCP 检索乐享知识库，自动引用历史决策作为上下文

三、车企行业场景工作流

结合车企典型业务流程（研发、质量、供应链、OTA），展示腾讯生态产品在汽车行业的落地路径

场景四：新车型研发协同（产品定义 → SOP）

1
TAPD → 车型项目立项
整车项目负责人在 TAPD 创建车型主项目，拆解为动力/底盘/车身/电子/智驾等子项目，自动同步至各领域负责人企微
2
腾讯文档 → 技术方案协同评审
各领域工程师在腾讯文档中编写 DVP（设计验证计划）、技术方案，多方在线评审、留痕审批，评审结论自动关联回 TAPD 需求
3
Codebody → ECU / 域控软件开发
嵌入式软件工程师在 Codebody 中开发域控制器软件（AutoSAR / 智驾算法），AI 辅助 MISRA-C 代码审查，提交自动关联 TAPD 软件需求条目
4
Workbody → DV/PV 测试工作流
测试计划触发 Workbody 专家工作流：自动生成测试矩阵 → 分配测试资源 → 汇总测试结果 → 不合格项自动创建 TAPD 问题单
5
乐享 → 车型开发经验库
SOP 后，设计文档、DVP 报告、问题复盘自动归档至乐享"车型知识库"，供后续平台化车型复用

场景五：质量问题追踪闭环（市场反馈 → 永久对策）

1
企微 → 售后 / 市场反馈触发
4S 店 / 客服通过企微提交质量问题，附带故障描述、诊断日志、现场照片，自动汇总至 TAPD 问题库
2
Workbody 8D 工作流
自动触发 8D 质量工作流：D1 组建团队 → D2 问题描述 → D3 临时措施 → 企微自动通知 QE / PE / SQE 进入
3
腾讯文档 → FTA / 鱼骨图协同分析
跨部门（质量/工艺/研发/供应商）在腾讯文档中协同进行故障树分析和根因定位，AI 辅助推荐可能原因
4
TAPD → 工程变更（ECR/ECO）
根因确认后自动创建工程变更请求，关联受影响车型/VIN 范围，Codebody 中完成软件/硬件变更实施
5
乐享 → 问题案例库 + FMEA 更新
问题关闭后自动归档至乐享"质量问题案例库"，同步更新 FMEA 知识库，供新车型预防性引用

场景六：供应商协同开发（需求下发 → PPAP 认可）

1
TAPD → 供应商需求下发
采购/SQE 在 TAPD 中创建零部件开发需求，关联 SOR（规格要求）、APQP 节点计划，通过企微同步至供应商对接人
2
腾讯文档 → 供应商方案提交 & 联合评审
供应商在腾讯文档中提交 DFM / 技术方案 / 试验计划，OEM 工程师在线评审批注，评审记录可追溯
3
Workbody → APQP 节点跟踪
Workbody 自动跟踪 APQP 各阶段节点：设计评审 → 样件提交 → DV/PV 完成 → PPAP 文件包提交，延期自动告警
4
乐享 → 供应商能力档案
项目完成后，供应商交付质量、问题历史、PPAP 文件包自动归档至乐享"供应商档案"，支撑后续供应商绩效评价

场景七：OTA 升级全流程（问题发现 → 全量推送）

1
TAPD → 软件问题/新功能需求
智驾/座舱/车身域的功能需求或问题修复在 TAPD 统一管理，自动路由至对应软件团队
2
Codebody → 软件开发 + AI Review
开发者在 Codebody 中完成功能开发和单元测试，AI 辅助 MISRA-C / CERT-C 静态分析，自动标注潜在风险代码
3
Workbody → 测试验证 + 灰度发布审批
触发 OTA 测试验证工作流：HIL 测试 → 整车集成测试 → 灰度发布审批（安全/法规/质量三级签审）
4
企微 + 腾讯文档 → 灰度监控 & 发布通告
灰度阶段通过企微机器人推送实时监控数据（升级成功率/异常率），全量发布时自动生成升级通告文档并推送给车主
5
乐享 → OTA 升级档案
升级完成后，软件版本、测试报告、审批记录、灰度数据自动归档至乐享，形成车辆软件版本可追溯档案

五、需推动各产品侧的能力清单

🔴 乐享

  • 开放 文档导入 API（支持腾讯文档、Markdown）
  • 支持 AI 自动打标签 / 分类 / 关联推荐
  • 开放 知识检索 API / MCP Server，供 Workbody Agent 调用
  • 支持 Webhook 通知（新知识入库 → 企微推送）

🔴 腾讯文档

  • 开放 「根据模板自动生成文档」API
  • 支持 AI 摘要 / Action Item 提取
  • 关联外部系统 ID（TAPD 单号 / Workbody 流程 ID / 会议 ID）
  • 文档变更 Webhook 通知

🟡 Workbody

  • 支持 MCP Client 协议，可调用外部工具
  • 支持 TAPD Webhook 触发工作流
  • 工作流上下文可传递给 Codebody
  • 提供 工作流模板市场（场景化预置模板）

🟡 Codebody

  • 支持 MCP 工具注册（调用自建服务 / 数据库）
  • Git Hook → TAPD 自动关联
  • Session 上下文可接收 Workbody 传入的任务信息

🔵 TAPD

  • 需求状态变更 → 企微群通知优化（支持模板化消息）
  • 开放 Webhook 出方向，触发 Workbody 工作流

🔵 Token Hub / MCP 网关

  • 统一 OAuth 接入文档 + SDK
  • MCP 网关统一管理和服务发现
  • 第三方 MCP Server 接入标准和审核流程

六、场景 × 能力缺口一览

场景 可推程度 现在能演示 需要补齐
需求 → 交付全流程 70% 可推 TAPD → Workbody → Codebody 链路 文档自动生成、乐享自动归档
故障应急响应 80% 可推 企微告警 → Workbody → Codebody → TAPD AI 自动根因分析、复盘自动归档乐享
会议 → 知识沉淀 40% 可推 企微 ↔ 会议 联动 会议转写 → 文档 → 乐享 全链路需各产品侧配合

Agent 驱动全流程 🔮 远期 — Workbody MCP Client + 乐享检索 MCP + 文档操作 MCP

图例说明： ✅ 可落地 = 现有 API 即可对接，1-2 周可出 Demo   ⚠ 需对接 = 需产品侧开放接口或小量开发   🔮 远期 = 涉及协议级改造（MCP 等），需中长期规划

核心策略：优先推"需求→交付"和"故障应急"两个场景，这两个场景覆盖的产品（TAPD/Workbody/Codebody/企微）已有较成熟 API，可快速做出客户可感知的 Demo。

下一步：内部拉会对齐各产品侧接口开放优先级，形成各产品需提交的需求单（TAPD），按场景分阶段交付。
