🚀 1. 性能提升：冷启动快 80%

变化了什么

Hermes 冷启动阶段（显示 "Initializing agent..."）从 ~4.3 秒 压缩到 ~0.9 秒，降幅 80%。覆盖 CLI、桌面端、TUI、cron 全平台。

指标0.18.x0.20.x改善
冷启动时间~4.3s~0.9s↓ 80%
推理思维流式输出❌ 完整生成后显示✅ 实时流式新增
Markdown 渲染按行渲染按 token 逐字渲染↓ 感知延迟

实操栗子

更新后直接体验，无需任何配置变更：

# 已有安装，直接更新
hermes update

# 新安装
curl -fsSL https://raw.githubusercontent.com/NousResearch/hermes-agent/main/scripts/install.sh | bash

# 验证版本
hermes --version
💡 实测体感：在 CLI 和桌面端首次交互时，原来需要等一个 "深呼吸" 的时间，现在几乎感觉不到等待。TUI 场景改善最明显。

🎤 2. 实时语音对话 & Barge-in（打断）

变化了什么

0.20.0 语音模式从「说完等待 → 等完整回复 → 听长音频」变为「边说边听边播报，随时打断」。

功能0.18.x0.20.x
TTS 播报时机等完整回复生成后一次性播报按从句流式实时播报
Barge-in 打断❌ 不支持✅ 说话中直接插嘴即可打断
多轮对话每次需手动触发一次唤醒，持续多轮
静默检测无忙碌感知，不抢话

实操栗子

# CLI 语音模式启动
hermes voice

# 桌面端：点击麦克风图标，或说唤醒词

# 对话中途直接说话即可打断，模型自动感知并响应
# 说出 "stop" 结束语音会话
✅ Barge-in 原理：模型接收到的 context 里内嵌了"用户已打断"的信号，所以打断后的回复会自然承接打断前的意图，而不是从头开始。

🔔 3. 本地唤醒词 & 多 Profile 语音路由

变化了什么

0.20.0 唤醒词检测完全在本地运行，音频不上云。支持自定义唤醒词，以及不同唤醒词触发不同 profile。

实操栗子：配置自定义唤醒词

# 在 config.yaml 中配置
voice:
  wake_word: "hey hermes"        # 自定义唤醒词，支持任意短语
  wake_engine: "openwakeword"    # 本地检测引擎，不上传音频
  multi_profile_routing: true   # 不同唤醒词路由到不同 profile

profiles:
  work:
    voice:
      wake_word: "hey work"
  personal:
    voice:
      wake_word: "hey home"
⚠️ 注意：唤醒词必须是「开放词汇」短语，不能是单字或极易误触的词。建议 2~4 个音节，如 hey hermes、小德小德。

📱 4. 跨平台语音消息接入

变化了什么

0.20.0 支持以下平台接收语音消息 → 自动转写 → 回复 → TTS 发回：WhatsApp、飞书（Lark）、钉钉（DingTalk）、LINE、QQ、微信（Weixin）、Photon。

实操栗子：配置飞书语音

# config.yaml
platforms:
  feishu:
    enabled: true
    voice:
      stt_provider: "openai"      # gpt-transcribe
      stt_language: "zh-CN"       # 强制中文转写
      tts_provider: "minimax"    # 平台适配 TTS
      tts_format: "opus"          # 自动适配平台格式
💡 统一语言解析：0.20 新增跨平台语言自动检测，解决「语音消息发出去变成英文转写」的经典问题——现在可以强制指定语言，或让系统自动检测。

🔬 5. Grounded Citations 可验证研究

变化了什么

0.20.0 研究类请求输出的每条 claim 都附有可验证来源：引用文本与实际页面文字精确匹配，而非 LLM 幻觉的摘要。

模式触发方式输出
Grounded Mode使用 grounded-citations skill 或 /research 命令每条 claim 带原文引用 + 页面链接
Fact-check Mode传入文档或 claim，用 /factcheck 命令三类结果：属实 / 不实 / 无法验证

实操栗子

# 在 skill 配置中指定来源域
grounded_citations:
  domains:
    - arxiv.org
    - github.com
    - official-docs.example.com
  factcheck_mode: true

# 用法示例（Hermes 对话中）
/research Gemini 3.6 Flash vs GPT-5.6 performance benchmarks 2026
# → 输出带精确来源引用的研究报告
✅ vs 0.18.x：0.18 的研究输出依赖模型自身知识，无引用验证机制。0.20 的 grounded citations 在引用匹配层做事实校验，claim 引用的是真实页面文字，而非 LLM 重述。

🤖 7. A2A v1.0 Agent-to-Agent 通信

变化了什么

0.20.0 Hermes 内置 A2A v1.0 协议实现，可与异构多 Agent 系统标准互联。这是 Issue #514 —— 社区最老的 Feature Request 之一。

功能说明
Agent 发现自动发现同网络内 A2A 兼容 Agent
标准 Wire ProtocolHTTP/WebSocket 上的 JSON-RPC 2.0
任务委派向其他 Agent 发送任务、接收结果
状态同步多 Agent 之间状态一致性

实操栗子

# config.yaml 配置 A2A
a2a:
  enabled: true
  agent_id: "hermes-primary"
  discover: true
  registry:
    - url: "http://agent-2:8100"
      role: "researcher"

# 在对话中委派任务
/hermes 请让 researcher agent 调研 Tesla FSD 最新进展
⚠️ 前置要求：对端 Agent 也必须支持 A2A v1.0 协议，不是任意 Agent 都能直接互通。

🌐 8. 出站 Webhook + HMAC 签名

变化了什么

0.20.0 Hermes 从「被动响应」变为「主动推送」——可向任意 HTTP 端点发送带签名验证的生命周期事件。

事件触发时机
session.start新会话创建
turn.complete每轮对话完成
tool.event工具调用完成/失败
delivery.retry消息发送重试

实操栗子

# config.yaml
webhooks:
  - name: "ci-dashboard"
    url: "https://ci.example.com/hermes-webhook"
    secret: "your-hmac-secret-key"
    events:
      - "session.start"
      - "turn.complete"
      - "tool.event"
    filter:
      platforms: ["cli", "desktop"]

# 接收方验签示例（Node.js）
const crypto = require('crypto');
function verifySignature(payload, signature, secret) {
  const expected = crypto.createHmac('sha256', secret).update(payload).digest('hex');
  return `sha256=${expected}` === signature;
}
✅ 集成场景：CI/CD Dashboard 监听 session 事件 → 自动记录工时；Home Assistant 监听 tool.event → 触发自动化；自建 APM 接收 delivery.retry → 监控消息送达率。

🗜️ 11. 上下文压缩重构

变化了什么

0.20.0 上下文压缩从「被动触发」变为「主动管理」，解决了长会话掉线索、压缩时大停顿等问题。

特性说明
Proactive Tool-result 修剪大 context window 模型主动识别低价值 tool result 并修剪
Per-turn 微压缩每个 turn 分散压缩成本，消除一次性大暂停
Guaranteed N 条用户消息尾最近 N 条用户消息永远保留，不被压缩
进度感知超时慢速摘要模型不再因超时失败
Ghost-skill 防御被修剪的 skill 不会再静默残存 session
Per-model 配置压缩阈值可按模型独立设置（token 绝对值）
# config.yaml
compression:
  enabled: true
  per_model_tuning:
    gpt-4o:
      max_context_tokens: 120000
      prune_threshold: 0.4
  guaranteed_user_message_tail: 5
  progress_aware_timeout: true
  ghost_skill_defense: true

🔐 12. 密码管理器集成（Bitwarden / 1Password）

变化了什么

0.19.0 API 密钥不再需要写在明文 .env 文件，通过 op:// 引用直接从密码库读取。

提供商引用格式状态
1Passwordop://vault/item/field✅ 官方支持
Bitwardenbw://item/field✅ 官方支持
# config.yaml 中使用 1Password 引用
providers:
  openai:
    api_key: "op://MyVault/openai-api/key"

secret_sources:
  - type: "1password"
    vaults: ["MyVault", "Work", "Personal"]
    precedence: ["MyVault", "Work"]
✅ 优势：密钥不落磁盘 CI 日志、环境变量快照；多人团队共享引用路径而非明文值； vault 锁定后自动失效。

⚠️ 注意：唤醒词必须是「开放词汇」短语，不能是单字或极易误触的词。建议 2~4 个音节，如 hey hermes、小德小德。

🌐 8. 出站 Webhook + HMAC 签名

变化了什么

0.20.0 Hermes 从「被动响应」变为「主动推送」——可向任意 HTTP 端点发送带签名验证的生命周期事件。

事件触发时机
session.start新会话创建
turn.complete每轮对话完成
tool.event工具调用完成/失败
delivery.retry消息发送重试

实操栗子

# config.yaml
webhooks:
  - name: "ci-dashboard"
    url: "https://ci.example.com/hermes-webhook"
    secret: "your-hmac-secret-key"
    events:
      - "session.start"
      - "turn.complete"
      - "tool.event"
    filter:
      platforms: ["cli", "desktop"]

# 接收方验签示例（Node.js）
const crypto = require('crypto');
function verifySignature(payload, signature, secret) {
  const expected = crypto.createHmac('sha256', secret).update(payload).digest('hex');
  return `sha256=${expected}` === signature;
}
✅ 集成场景：CI/CD Dashboard 监听 session 事件 → 自动记录工时；Home Assistant 监听 tool.event → 触发自动化；自建 APM 接收 delivery.retry → 监控消息送达率。

🗜️ 11. 上下文压缩重构

变化了什么

0.20.0 上下文压缩从「被动触发」变为「主动管理」，解决了长会话掉线索、压缩时大停顿等问题。

特性说明
Proactive Tool-result 修剪大 context window 模型主动识别低价值 tool result 并修剪
Per-turn 微压缩每个 turn 分散压缩成本，消除一次性大暂停
Guaranteed N 条用户消息尾最近 N 条用户消息永远保留，不被压缩
进度感知超时慢速摘要模型不再因超时失败
Ghost-skill 防御被修剪的 skill 不会再静默残存 session
Per-model 配置压缩阈值可按模型独立设置（token 绝对值）
# config.yaml
compression:
  enabled: true
  per_model_tuning:
    gpt-4o:
      max_context_tokens: 120000
      prune_threshold: 0.4
  guaranteed_user_message_tail: 5
  progress_aware_timeout: true
  ghost_skill_defense: true
