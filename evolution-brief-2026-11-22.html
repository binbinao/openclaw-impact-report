00一句话

本期是「预测收敛」的一期，也是「归因纠偏」的一期。容量轴：轮转时刻被算准到秒（10:22:19），但预告的 09:37–09:40 偏早 45 分钟，偏差倍数 2.27× 恰好等于「日平均速率 ÷ 心跳速率」—— 一条可以事前算出的比值，而不是随机误差。外部源轴：arXiv 首发即 5/5，却一篇新内容也没有，因为 11-20/11-21 是 arXiv 的非公告日，id 差集为 0 是**周末常态**而非采样损失。成本轴：把作业耗时拆成请求数后，arXiv 从「主因」变成「4.8%」，HN 的 11 个串行请求才是 90%。

Headline 01 · 容量

轮转被 3 个字节触发；最后一公里要 8 个格点（80 分钟），不是 35 分钟

/root/.hermes/logs/errors.log → errors.log.1 · 2026-11-21 10:22:19 · 2,097,050 B

轮转确实发生了，且时间可以逐秒复算。P177 快照（09:02:19）时文件 2,096,315 B，阈值 2,097,152 B（2 MiB，规则 W），余 837 B。P177 用日平均 34,334 B/日 得 ETA 35 分钟 → 09:37–09:40。

实测：.1 的最后一条记录是 10:12:19（2,097,050 B），新文件首条是 10:22:19 —— 轮转发生在「下一条 105 B 记录会把文件推到 2,097,155 B、超出阈值 3 字节」的那一刻。正算式：

ceil((2,097,152 + 1 − 2,096,315) / 105 B) = ceil(838 / 105) = 8 个格点
8 × 600 s = 80 min  →  09:02:19 + 80 min = 10:22:19  ← 与实测同秒

为什么 P177 会偏早 2.27 倍？把 11-19 这一天按小时切开就一目了然：

时段记录字节构成
00–07h、09–23h（23 个小时）6 / 小时630 / 小时weixin Session expired，600 s 等间隔（心跳）
08h（1 个小时）6819,844cron 作业窗口：结构性 ERROR + WARNING 突发
全日20634,334心跳 14,490 B（42.2%）+ 突发 19,844 B（57.8% 集中在 4.2% 的时间里）

日平均 = 34,334 ÷ 24 = 1,431 B/h，而心跳速率只有 630 B/h —— 比值 2.27。09:02→10:22 这段窗口里一次突发都没有，所以真实速率就是心跳速率。误差倍数可以事前解析写出：

规则 FY · 新 轮转 ETA 必须按「当前所处分量」的速率计算；日平均的偏离倍数 = 1 + B ÷ (24 × H)，其中 H 为心跳字节/小时、B 为当日突发字节。errors.log：1 + 19,214/15,120 = 2.27×。同一公式作用于 agent.log：1 + 24,284/295,920 = 1.08× —— 所以「日平均」在 agent.log 上几乎无害，在 errors.log 上却能把 80 分钟报成 35 分钟。同一条经验在两个文件上，一个是 8% 误差，一个是 127% 误差。

附：6 份现存 errors.log.1 的终结尺寸与 2 MiB 的差值为 29 / 95 / 101 / 102 / 137 / 160 B —— 全部小于「单条最大记录 ≈ 160 B」，这与「先判后写」（size + 下一条 > 阈值即轮转）完全一致，也是 P124 记录的 516 B 尺寸散布的真正来源。

Headline 02 · 外部源

arXiv 首发 5/5，然后交回 0 篇新论文 —— 而 P177 记的「38.1 h 滞后」是 +8 h 的时区错

batch 2611.26627–26613 · published 2026-11-19T18:57–18:59Z · 与 P177 同一批次

本期 knowledge_ingest.py 一次成功，没有重试（对比 P177：首发 0/1 → 128 秒后重试 5/5）。但返回的 5 篇与 P177 逐 id 相同：2611.26627 / 26624 / 26619 / 26617 / 26613。id 差集 = 0。

这不是采样损失。11-20（周五）、11-21（周六）是 arXiv 的非公告日（周日–周四公告，20:00 ET），所以「最新一批」仍是 11-19 13:59 ET 那批。滞后 54.03 h = 正常 30.03 h + 24 h（周末），与规则 CB/EQ 的公告日历模型一致。

规则 FZ · 新 · 同时是一处历史更正 P177 记录「滞后 38.1 h」。用同一批次、同一公式复算：11-19 18:59Z → 11-21 01:03Z（P177 快照的 UTC 时刻）= 30.09 h。差额恰好 +8.00 h —— 把 CST 快照当成了 UTC。时间差计算的两端必须同基准，并在报告里写出两个绝对时刻（UTC）；否则 8 小时的相位差会伪装成「公告变慢」。P174 / P175 / P176 均为 30.0 / 30.12 / 30.15 h，P177 是唯一的异常点。

同分钟三探针（用脚本自己的 URL 构造器，规则 EC）：1.62 s → 0.39 s → 0.39 s，字节全部 13,279 B、5 entries、newest = 2611.26627 ⇒ 源健康、P177 的冷启动形态未复现。但注意：可用性恢复 ≠ 有新内容。把「5/5 成功」记成正向信号，等于把「周末」记成「修复」。
