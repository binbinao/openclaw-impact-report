cirq 是 Google Quantum AI 的开源量子计算框架。本技能（7 个文件：SKILL.md + 6 个 references）为 Agent 提供面向 Google 量子硬件 的线路设计、噪声建模与表征实验的方法论与代码模式。
技能定位边界（SKILL.md 明确声明）：
✅ 适用：Google 硬件（cirq-google）、噪声感知线路、表征实验、NISQ 线路、参数扫描、ReCirq 实验模式
❌ 不适用：IBM 硬件 → qiskit；量子机器学习 → pennylane；物理仿真 → qutip

3. 各硬件后端访问前提（按需激活）

3.1 Google Quantum Engine（门槛最高）

"Google hardware access is restricted to approved users."（hardware.md）
  • 审批：需 Quantum Engine 访问审批（非公开申请，面向研究机构/合作方）
  • GCP：一个开启 Quantum Engine API 的 Google Cloud 项目
  • 凭据：本机配置 Application Default Credentials（ADC），或 GOOGLE_CLOUD_PROJECT 环境变量
  • 处理器：需知道被分配的 processor id（如 weber / sycamore / willow）
本地模拟路径：cg.Sycamore / cg.Sycamore23 / SimulatedProcessorWithLocalDeviceRecord 可无需真机做拓扑 + 噪声仿真 —— 2026-09-03 实测 Sycamore 54 qubits / 88 edges GridDevice 本地可实例化。

4. 仿真资源约束（本地跑表征实验的关键限制）

模拟器复杂度建议上限说明
cirq.Simulator（态矢）O(2^n)~30 qubits 内纯态，快
cirq.DensityMatrixSimulatorO(2^2n)~12-14 qubits 内噪声仿真必须用它（混合态），内存随 n 平方爆炸
cirq.StabilizerSimulator多项式大量 qubits仅限 Clifford 线路
工程判断：带噪表征实验（RB / XEB / 读出标定）通常跑 1-6 qubits → DensityMatrixSimulator 完全够用；若目标线路 > 12 qubits 想加噪声，先剪枝或改用噪声模型抽样。

5. 官方实验 API（表征实验入口，实测探测 2026-09-03）

cirq 1.6.1 自带实验套件（cirq.experiments）。技能内 RB/XEB 手写代码是简化示意（不跟踪 Clifford 逆），实际应调用官方 API：

实验API返回
单比特 RBsingle_qubit_rb(sampler, qubit, parameters) / parallel_single_qubit_rbRandomizedBenchMarkResult（含 pauli_error / plot）
读出标定estimate_single_qubit_readout_errors(sampler, qubits=...)SingleQubitReadoutCalibrationResult
读出混淆矩阵measure_confusion_matrix(sampler, qubits)TensoredConfusionMatrices
XEBxeb_fidelity(...) / TwoQubitXEBResult保真度

8. 结论

纯本地跑通（仿真 + 表征）的最低前提只有三个：Python ≥ 3.11、cirq==1.6.1、matplotlib/scipy/numpy（画图拟合）。

真机任何一家的前提都是对应平台的 API key / 审批 + vendor 包。Google 真机门槛最高（审批制），但其设备模型（Sycamore / Sycamore23）本地可完全模拟 —— 用于"面向 Google 硬件设计 + 表征"的研究目的已足够。
