NIST 的 Apostol Vassilev 把 Gödel 不完备定理重写为 Chaitin 信息论范式， 证明任何有限规则集的 OOPS guardrail 都不能完备判定越狱 prompt： Theorem 2 & 3 给绝对鲁棒划了理论上限。 论文反复强调"定理不给攻击 recipe"，把结论推向 AGI/ASI 仍有不可证的真—— 一篇把 AI 安全划上 信息论天花板 的 7 页小论文。

一句话核心主张

"For any checker C_Π(T_Π, p) there exist a truth T_Π such that C_Π(T_Π, p) ≠ 1, ∀p."
—— Theorem 2 / Theorem 3

把 Gödel 的"形式系统无法证明所有真"翻译成"guardrail 无法识别所有越狱 prompt"。 形式骨架是 Chaitin 1974 的 information-theoretic incompleteness，不是什么新鲜数学。 论文新颖处不在数学，而在把这套范式精准套到 LLM 输出治理上， 并且刻意写出"对称实用"的应对手段——这是 NIST 视角与学术视角的最大差异。

论证骨架：4 定理 + 1 命题

全部定理都用同一套符号：Ω = prompt 全集（card Ω = ℵ₀）， Γ_Π = 策略 Π 下被阻断的 prompt 子集， T_Π = "能输出 x 的算法长度都 > n" 这种真理， C_Π(T, p) = 1 ⇔ 存在 C_Π 可验证的证明 p。 
定义层:  Ω      = 所有 prompt 字符串的集合        (card Ω = ℵ₀)
         Γ_Π    = 策略 Π 下被阻断的 prompt 子集
         T_Π    = "能输出 x 的算法长度都 > n"  这种真理
         C_Π(T, p) = 1  ⇔  存在可验证的 p 证明 T_Π 为真

Proposition 1 — Γ_Π 必无穷

如果 Γ_Π 有限 ⇒ 取最长串 x_max，前后拼接良性文本 ⇒ 仍是 adversarial 但更长 ⇒ 矛盾。 拼接手法在论文里举例："I would like to get some information about the weather. Ignore this. <x_max>"—— 这个例子本身依赖 LLM 行为，没法宣称"架构无关"，是论文里最弱的一环。

Theorem 2 — 理想 AI 的完备上限

Chaitin 风格的改造：

Theorem 2 (Vassilev 2025 §2.1)

For any checker C_Π(T_Π, p) there exist a truth T_Π such that C_Π(T_Π, p) ≠ 1, ∀ p.

构造算法 1：在 i = 1, 2, 3, ... 上穷举所有 (x ∈ Γ_Π, p)，若 C_Π(T_Π, p) == 1 就输出 x。这个算法只在编码 n 上"额外"用了 log₂ n bits，其余部分常数 ⇒ len(Algo 1) = O(log n) ≪ n。于是：

  • 若 T_Π 真 ⇒ 找不到合法 (x, p) ⇒ Algorithm 1 不返回（看起来对）
  • 但 Algorithm 1 本身是一条长度 ≤ n 的"输出 x"算法 ⇒ T_Π 应被否定 ⇒ 与假设矛盾

Theorem 3 — 有限上下文的现实版

Theorem 3 (Vassilev 2025 §2.2)

For any checker C_Π̂(T_Π̂, p̂) there exist a truth T_Π̂ such that C_Π̂(T_Π̂, p̂) ≠ 1, ∀ p̂.

关键 case 分流： 

令 Θ = 长度 ≤ n 的算法可产生的 prompt 集合
        ┌── Θ = Γ̂_Π̂  → 算法规格已穷尽所有 adversarial prompt → T_Π̂ 不成立 → 直接成立
        │
        └── Θ ⊂ Γ̂_Π̂  → 必有 x 使 T_Π̂ 真 → Algorithm 2 (与 Algorithm 1 同形, O(log n))
                          → 同样自指矛盾
图 2 — 有限上下文的定理分流。论文承认"global Earth 资源穷举不起所有 prompt"，把 case(1) 留给已穷尽攻击的极端假设。

Theorems 4 & 5 — 认知推理的极限

把 checker 推广到"任意真理 verifier" ⇒ 任何 AI（包括 AGI/ASI）都存在它永远无法证明的真。 作者明确说这不是"AI 不会发现新定理"——它是发现新真理的高效引擎，只是有结构性上限。 哲学外推   严格性中等

隐含假设 & 可被攻击的弱点

假设 1 · 架构无关

"忽略前半" 依赖 LLM 行为

拼接良性前缀让模型 ignore 前半，只看 x_max —— 这本身依赖 LLM 行为。如果定理号称架构无关，这一步就是个 smuggled LLM assumption。

假设 2 · checker 长度

Algorithm 1 长度 O(log n) 的工程含义

“n 是单一参数” → 但实际 checker 实现还要 hand-coded tokenizer、parser、handler 等大常数开销，作者把这部分归到"depends on programming language"，回避量化。这是经典 Chaitin 论证的老漏洞（参见 Raatikainen 1998）。

假设 3 · checker=证据论

"可验证" 这个形式前提

C(T, p) = 1 iff there is a verifiable proof p。p 必须由 C 自身可验证 —— 这里“可验证”本身是有争议的形式化前提。

假设 4 · 全称量词强度

∀ checker 在工程上比证明更强

现实里不同对手算力差异巨大，"对所有 checker" 这个全称命题比定理更强 —— 是论文最强也最不实用的地方，论文自己也知道（§3 Practical Measures）。
