🔬 3. 控制实验：规则 AT 被证伪（本期核心）

第 141 期以「同分钟交替对照」判定编码为决定性变量，并据此把 urlencode 补丁列为 P0。本期复现同一实验（同一主机、同一 UA、两种查询串交替、同一分钟）：

期次 / 日期查询串形态成功率耗时 / 响应
P141 · 2026-10-16raw（未编码冒号，脚本现用）0 / 1012.3–15.4 s TimeoutError ×7 · HTTP 429 ×3
P141 · 2026-10-16percent-encoded8 / 80.45–0.75 s · HTTP 200 · 14,779 B
P142 · 2026-10-17raw（同一脚本、未改动）3 / 30.45–0.49 s · HTTP 200 · 14,476 B
P142 · 2026-10-17percent-encoded0 / 3TimeoutError 20.3 s ×3
结论：编码不是决定性变量，规则 AT 的强断言被直接反例证伪。
  • 两次实验的对照臂结果完全反转，而两次中成功的那一臂耗时都只有 0.45–0.75 s、体积都是 ~14.5 KB —— 说明两臂都在打同一个 arXiv API 并拿到真实结果，区别不在「能否到达」，而在当时那一刻哪一形态被服务。
  • 零代码改动即恢复：knowledge_ingest.py 本期未做任何修改，arXiv 摄取成功返回 5 篇（P141→P142 无补丁落地）。⇒ 代码从来不是（唯一）原因。
  • 可操作后果（重要）：P141 的 P0 补丁若被应用，今天会立刻打断 arXiv 摄取（encoded 0/3）。该建议必须撤销或改为条件性。
📐 新规则 AU · 对照实验须跨日复现才能归因代码缺陷
单一分钟级对照不能定位代码缺陷 —— 它只消除了「时刻」混淆，未消除「效应本身随时间翻转」。判定代码缺陷须在 ≥2 个不同的日子各做一次同形态对照，只有结果稳定才可归因；结果翻转 ⇒ 真正变量在外部（可用性窗口），与规则 AQ 的「护栏型指标 = 外部依赖可用性指标」同源。
本轮的两个实验合起来恰好构成一个完整的「稳定 vs 翻转」判别：单看 P141 会得出编码决定性，单看 P142 会得出编码有害；只有并置两者才得到正确答案 —— 两者都不可归因。
