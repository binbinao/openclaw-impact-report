🔴 P0 · 修复网关重启风暴（Respawn Storm）
每日 ~1,801 条 gateway.run ERROR + ~1,801 条 hermes_cli.gateway WARNING = ~3,602 条（38.9% 全文件占比）。根本原因：cron job 在 gateway 已运行时尝试重启。修复：在 cron job 启动脚本中添加 PID 存活检测前置检查。若 PID 3433647 仍在运行，跳过启动步骤。消除后可减少 38.9% 日志噪声，恢复非洪水组件在窗口中的可见性。
🟠 P1 · 清理无效 plugin.json 文件
每日 ~5,403 条 WARNING（58.4% 全文件占比）。三个签名完全一致：.cursor-plugin、.claude-plugin、.codex-plugin 的 plugin.json 声明的 Agent Plugins schema 不被当前版本支持。修复：删除或更新 ~/.hermes/profiles/reviewer/plugins/superpowers/ 下的这三个插件目录。消除后可将日志噪声减少 58.4%。
🟡 P2 · 配置 API_SERVER_KEY 或禁用 api_server
每日 ~118 条 ERROR（1.3% 全文件占比），每 5 分钟一次。修复：在 config.yaml 中设置 API_SERVER_KEY 或将 api_server 平台配置注释掉。
🟡 P3 · 修复 approvals.mode 配置
在 config.yaml 中将 approvals.mode 从 'auto' 改为 'manual'、'smart' 或 'off'。消除后减少少量 WARNING 噪声。
🔵 P4 · 启用备选学术数据源
arXiv API 自 P74 以来 18 期中仅 11.1% 成功。建议启用 Semantic Scholar API（free tier 100 req/day）或 CrossRef API 作为备选，在 arXiv 连续失败 ≥3 期时自动切换。
⚪ P5 · 升级 weakness_scan.py 以修复三重盲区
盲区已连续 51 期（>4 个月）。建议：(a) 添加 WARNING 级别聚合检测规则，(b) 跨组件签名聚合，(c) 全文件周期扫描模式替代仅尾窗 500 行策略。
