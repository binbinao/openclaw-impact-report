明确利益相关者期望

Stakeholder Expectations Definition
系统设计

🛠️ CAE 工程场景

  • 识别上游设计师 / 强度工程师 / 试验工程师 / 适航审查方 / 客户（OEM）— 拿到载荷谱、工况清单、试验大纲、适航条款
  • 形成"运行使用构想（ConOps）"：每个分析工况的边界条件、初始/约束条件、求解精度要求、报告交付物
  • 业主期望示例：碰撞仿真在 5ms 内完成、座椅鞭打工况加速度误差 ±2g、热仿真 30 万网格 4h 内出解
LS-DYNA ANSYS Workbench iSight HyperStudy 工况矩阵

📐 MBSE 方法论场景

  • SysML 用例图（Use Case Diagram）识别系统利益相关者：飞行员、维修技师、调度、空管
  • 需求图（Req Diagram）建立 Stakeholder → Need → System Requirement 的追溯链
  • 运行使用构想（OV-1 Operational Viewpoint）使用 Capella / Cameo / Rhapsody 建模
Cameo Systems Modeler Capella Rhapsody SysML v2

🏭 A3 智能制造场景

  • 利益相关者：车间主任（要可执行的作业指导）、工艺工程师（要符合 PFMEA）、QA（要可追溯）、合规官（要符合 ISO 9001/IATF 16949）
  • 运行使用构想：作业员拿着平板在工位上一边看图一边作业，每步扫码防错，发现异常立即上报
  • 关键期望拆解：换型时间 ≤15min / 关键工序防错率 100% / 视觉化覆盖率 ≥95%
PBOM PFMEA SOP MES 天枢大模型
💡 NASA 关键提示：利益相关者识别必须"先于"项目启动。冲突的处置权要在阶段 A 前明确（手册 4.1 节）。
🎯 A3 落地建议：把"业主期望"做成一页《智能制造作业指导书期望清单》，列出 8-12 个关键 KPO（关键业主期望），每条对应一个质量门。

逻辑分解

Logical Decomposition
系统设计

🛠️ CAE 工程场景

  • 功能分解：B 白车身 → 车门 → 内板/外板/加强板；载荷分解：弯曲 + 扭转 + 侧碰 + 顶压
  • 物理分解：1D 梁单元 → 2D 壳单元 → 3D 实体单元；模型层级总成 → 子系统 → 组件 → 网格
  • 建立"系统-子系统-组件-参数"四级结构树，每层有对应的 DOE 任务和分析目标
功能树 PBS（产品分解结构） WBS（工作分解结构） Ansys Workbench Project Schematic

📐 MBSE 方法论场景

  • SysML Block Definition Diagram (BDD)：系统 → 子系统 → 组件 → 部件
  • Internal Block Diagram (IBD)：接口 + 端口 + 流向
  • 功能分析 (Activity Diagram) + 状态机 (State Machine) + 时序 (Sequence)
BDD IBD Activity Diagram Sequence Diagram

🏭 A3 智能制造场景

  • 产品树：PBOM → 装配体 → 部件 → 工序 → 工步 → 操作 → 关键特性
  • 16 业务对象：A3 系统把 PBOM 拆为"工序/工步/工具/物料/参数/SPC/防错/工时"等业务对象
  • 分解逻辑：先按装配序列（Order of Operations），再按工艺路线（Routing），最后按工序内工步细分
PBOM 结构树 Routing 16 业务对象 PFMEA
💡 NASA 关键提示：分解必须"迭代+递归"——一个组件可能向下 5 层，另一个只需 2 层，依据是复杂度与风险（手册 4.3 节）。
🎯 A3 落地建议：业务对象枚举是关键——把 16 个对象列成矩阵（PBOM → 作业指导书 → MES 输入），每个对象写明字段、来源、消费者、验证方法。

设计方案定义

Design Solution Definition
系统设计

🛠️ CAE 工程场景

  • 设计备选方案：拓扑优化 vs 尺寸优化 vs 形貌优化；铸造 vs 锻造 vs 冲压；钢 vs 铝 vs 复材
  • 权衡研究（Trade Study）：加权矩阵评估重量 / 成本 / 性能 / 制造性 / 维修性，每项赋权重打分
  • baseline 锁定：选定方案后冻结设计参数，作为 PDM 中的"baseline part"，进入后续 CAE 与图纸迭代
Topology Opt Altair Inspire Genesis Design 加权评分矩阵

📐 MBSE 方法论场景

  • Parametric Diagram (SysML) + Trade Study 工具：方案库 → 评估准则 → 评分 → 选定
  • 把设计准则 (Design Constraint) 写成 Constraint Block，自动校验设计参数
  • 设计包：含 3D 模型、2D 图、仿真报告、试验大纲、PFMEA、SPC 计划
Parametric Diagram Constraint Block Trade Study

🏭 A3 智能制造场景

  • 作业指导书方案选择：纯文字版 / 图文版 / 视频版 / AR 辅助版 / AI 实时问答版
  • 权衡：新手作业员（要图文配视频）vs 熟手（要快查表）vs 异常处理（要 AI 问答）
  • AI 生成方案：天枢 LLM 输入 PBOM + 历史作业指导书 → 输出图文步骤 + 关键参数 + 报警条件
A3 方案矩阵 图文+视频 AR 辅助 AI 问答
💡 NASA 关键提示：设计方案的验证是"持续迭代+递归"——选完后还会回头被验证（手册 4.4 节）。
🎯 A3 落地建议：方案锁定的标志是"三可"——可生成 / 可审批 / 可下发。三可没满足前不进 D 阶段。

产品实施执行

Product Implementation
产品实现

🛠️ CAE 工程场景

  • 三种实现方式：购买（标准件库） / 制造（自建模型） / 重用（历史项目模板）
  • 网格划分策略：关键区域细化（边、孔、焊点）+ 远场粗化 + 过渡区渐变；网格收敛验证 ≥ 3 套网格
  • 求解器选择：隐式（线性/非线性静力）vs 显式（冲击、碰撞）vs 模态（NVH）vs CFD
ANSYS Meshing HyperMesh ABAQUS Star-CCM+ Fluent

📐 MBSE 方法论场景

  • 设计模型（MBSE）→ 物理实现（CAD/CAE/MBD）的"模型桥"：SysML 仿真包 + FMI/FMU 联合仿真
  • 采购标准件（COTS）→ 在 MBSE 模型中用 Stereotype 标注 + 引用外部库
  • 重用历史模型：在 Teamcenter/3DExperience 中按"成熟度（TRL）"分层管理
FMU/FMI 3DExperience Teamcenter

🏭 A3 智能制造场景

  • 实施执行：购买（标准工艺） / 制造（自研工序） / 重用（历史作业指导书）三种模式
  • AI 生成：天枢 LLM 把 PBOM 变更通知 + PFMEA + 历史工艺 → 生成作业指导书初稿（火箭班自研多模态输出）
  • 质量门：初稿 → 工艺工程师审核 → 车间试运行 → 主管签字 → 入库
天枢 LLM 火箭班 LLM Agent 知识库 RAG
💡 NASA 关键提示：重用产品必须重新验证——"出生于其他系统的验证，不能依赖"（手册 5.1 关键点）。
🎯 A3 落地建议：AI 生成的作业指导书必须经过"四步质量门"——自动校验 / 工艺审核 / 车间试运行 / 异常样本抽检。

  • 集成层次：组件 → 子系统 → 系统 → 系统之系统（SoS）；每层有 ICD（接口控制文档）
  • SysML Internal Block Diagram 标注接口与端口类型
Integration Plan ICD SysML IBD Interface Block

工序卡 装配作业包 MES ANDON

🎯 A3 落地建议：作业指导书必须"按工位集成"而非"按工序堆叠"——工位是 MES 的最小执行单元。
07

产品验证

Product Verification
产品实现

🛠️ CAE 工程场景

  • 验证 = "建造正确"：仿真结果 vs 设计规范（应力 ≤ 允许值、模态 ≥ 目标频率、NVH ≤ 限值）
  • 验证方法：分析（CAE 仿真） / 试验（台架） / 检查（图纸） / 演示（Demo）
  • 网格无关性验证：3 套网格（粗/中/细）关键响应误差 < 5%
网格收敛 DOE 台架试验 证书签署

📐 MBSE 方法论场景

  • 验证矩阵（Verification Matrix）：每条需求 → 验证方法（Analysis/Test/Inspection/Demo）→ 接受准则
  • 模型基测试：SysML 仿真执行（Simulation Toolbox）→ 自动跑参数化场景
  • 独立验证：测试工程师不是建模工程师（避免"自己验证自己"）
Verification Matrix Modelica Simulink

🏭 A3 智能制造场景

  • 验证 = "作业指导书是否准确描述了工艺"：文本 vs 现场工艺规范、参数对、关键控制点对
  • 验证手段：自动校验（LLM 自检关键参数） / 工艺审核（人工） / 试运行（小批量）
  • 关键防错：扭矩、焊点、压装、注液——必须 100% SPC 覆盖、SPC 规则触发报警
LLM 自检 工艺审核 SPC 试运行
💡 NASA 关键提示：验证 vs 确认 -- 验证是"建造正确"，确认是"建造正确的"（手册 5.3-5.4 反复强调）。
🎯 A3 落地建议：验收准则量化——"扭矩 80±5 N·m"，而不是"扭矩合适"。

产品确认

Product Validation
产品实现

🛠️ CAE 工程场景

  • 确认 = "建造正确的"：仿真结果 vs 真实试验数据、vs 用户实际使用场景
  • 典型场景：仿真碰撞波形 vs 真实气囊点爆波形、仿真 NVH vs 实车路试、仿真热管理 vs 实车高温试验
  • 确认偏差 > 10% 必须回溯建模假设（材料模型、边界条件、网格）
试验相关性 Model Correlation Corner Case

📐 MBSE 方法论场景

  • 确认矩阵（Validation Matrix）：每条需求 → 模拟/真实场景下的运行试验
  • 用户参与（User in the Loop）：飞行员/操作员在 VR/HIL 环境下真实操作
  • 运行剖面（Mission Profile）覆盖：高频关键场景 + 极端工况
Validation Matrix HIL VR/XR

🏭 A3 智能制造场景

  • 确认 = "作业指导书能否真的让作业员在真实工位完成作业"：现场试制 + 异常情况下可读性
  • 真实场景验证：老员工 / 新员工 / 多语种 / 异常情况（漏件、错件、工具失效）
  • AI 作业问答：作业员现场提问，AI 给出可执行步骤（能否覆盖 95% 异常？）
现场试制 多语种 AI 问答 异常路径
💡 NASA 关键提示：确认试验必须在"真实环境或模拟环境"下进行（手册 5.4）。
🎯 A3 落地建议：作业指导书必须经过"新员工盲测"——给新人使用 AI 作业指导书独立完成作业，统计成功率。

技术管理

  • 需求变更自动影响分析：哪些设计、哪些接口、哪些测试需要同步变更
  • 双向追溯：向上 → 上层需求/法规；向下 → 设计 → 实现 → 测试 → 验证
SysML Requirement Traceability

🏭 A3 智能制造场景

  • 需求 ID 规则：PBOM-CHG-2026-08-001 ↔ WI-2026-08-001（作业指导书 ID）↔ SOP-...
  • 变更触发：PBOM 变更 → 自动评估影响工序 → 自动生成"需求变更草案" → 工艺工程师审核
  • 追溯：PBOM 变更 → 工序 → 步骤 → 工具 → 物料 → PFMEA → SPC → 培训材料，全链路
PBOM 变更 ID WI 文档 PFMEA 链接 变更流
💡 NASA 关键提示：追溯性是"成功确认产品需求的关键"（手册 4.0 关键点）。
🎯 A3 落地建议：建立"作业指导书需求图谱"——每张 WI 卡上能看到：来自哪个 PBOM 变更、关联哪些 PFMEA、对应哪些 SPC 规则、培训过哪些人。

技术风险管理

Technical Risk Management
技术管理

🛠️ CAE 工程场景

  • 5×5 风险矩阵：可能性 × 严重性；典型风险：材料模型不准、网格发散、求解器不收敛、license 不足

📐 MBSE 方法论场景

  • MBSE 实施风险：组织接受度、工具成熟度、模型维护成本、人员流失
  • 技术风险：模型保真度不足、跨域模型语义不一致、版本管理混乱
Risk Register MBSE Maturity

🏭 A3 智能制造场景

  • AI 风险：幻觉（关键参数编造）、上下文遗忘（漏工序）、合规风险（违规工艺）
  • 缓解：四步质量门（自检/审核/试运行/抽检）+ 关键参数 100% 人工复核 + 黑名单关键词
  • 业务风险：用户抵触（不愿用 AI 生成）、变革管理、试错成本
  • 合规风险：AI 生成内容是否可作为正式工艺文件？合规官职责边界？
AI 幻觉 合规边界 变革管理 黑名单
💡 NASA 关键提示：风险"5 个特征"——识别/分析/缓解/接受/沟通/监测（手册 6.4）。
🎯 A3 落地建议：AI 生成作业指导书必须"先人工、后 AI、再人工"——工艺工程师构造 prompt → AI 生成 → 工艺工程师复核。

📊 17 流程 × 3 场景 对照速查表

系统设计（4 流程）

重点：利益相关者期望识别 + 需求定义 + 逻辑分解 + 设计方案。A3 场景差表现为：PBOM 变更通知没及时识别业主期望 → 作业指导书偏差。

产品实现（5 流程）

重点：验证 vs 确认区分、A3 场景落地为"作业指导书自检 vs 试运行确认"。AI 不能跳过验证门。

技术管理（8 流程）

重点：需求/接口/风险/CM/数据管理，是 A3 项目的"软基础设施"。忽视任一环节，AI 生成作业指导书会失控。

CAE 工程

工具链：ANSYS / ABAQUS / Fluent / Star-CCM+ / HyperMesh / LS-DYNA / Altair。CAE 强证据来自试验验证与 corner case 覆盖。

MBSE 方法

工具链：Cameo / Capella / Rhapsody / DOORS / Polarion / Modelica。MBSE 是系统工程流程的"机器可执行"实现。

A3 智能制造

工具链：天枢 LLM / 火箭班 / PBOM / PLM / MES / PFMEA / SPC。AI 是放大器，流程纪律决定放大方向。
